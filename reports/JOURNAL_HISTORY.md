# История развития Events Journal

## Обзор

Events Journal (журнал событий) прошел через множество улучшений и исправлений, начиная с базовой функциональности и заканчивая полной совместимостью с database journal.

## Основные этапы развития

### Этап 1: Базовая функциональность

**Реализовано**:
- Отображение событий found и lost
- Базовая структура таблицы
- Загрузка данных из JSON файлов

**Проблемы**:
- Пустая колонка Time для объектов без found события
- Неправильное отображение изображений
- Отсутствие обновления в реальном времени

### Этап 2: Исправление колонки Time

**Проблема**: Колонка Time была пустой для объектов, у которых есть только lost событие.

**Решение**:
```python
'time': found_event.get('ts') if found_event else (lost_event.get('ts') if lost_event else '')
```

**Результат**: Колонка Time всегда заполнена.

### Этап 3: Исправление отображения изображений

**Проблема**: Изображения не показывались, в Found image не было данных, в Lost image показывалась строка с именем файла.

**Решение**:
- Добавлена проверка существования файлов в `ImageDelegate`
- Исправлена логика создания `QTableWidgetItem` для пустых ячеек
- Добавлена отладочная информация для отсутствующих изображений

**Результат**: Изображения показываются для существующих файлов.

### Этап 4: Правильное отображение source_name

**Проблема**: Показывалось `source_1`, `source_2` вместо `Cam1`, `Cam2`.

**Решение**:
```python
source_display = ev.get('source_name', '')
if not source_display and ev.get('source_id'):
    source_display = f"Cam{ev.get('source_id')}"
```

**Результат**: Правильное отображение имен камер.

### Этап 5: Унификация структуры таблицы

**Проблема**: Таблица не соответствовала структуре `DatabaseJournalWindow`.

**Решение**:
- Заголовки: `['Event', 'Time', 'Time lost', 'Information', 'Preview', 'Lost preview']`
- Группировка found и lost событий в одной строке
- Структура соответствует базе данных журналу

**Результат**: Единообразная структура с database journal.

### Этап 6: Обновление в реальном времени

**Проблема**: Журнал не обновлялся автоматически.

**Решение**:
```python
self.update_timer = QTimer()
self.update_timer.timeout.connect(self._reload_table)
self.update_timer.start(5000)  # 5 секунд
```

**Результат**: Автоматическое обновление каждые 5 секунд.

### Этап 7: Исправление одинаковых изображений

**Проблема**: В журнале отображались одинаковые изображения для событий "найден" и "потерян".

**Решение**:
- Исправлен `JsonLabelJournalDataSource._map_item()` для правильной обработки разных типов событий
- Для событий `found` используется поле `timestamp`
- Для событий `lost` используется поле `lost_timestamp`
- Разные пути к изображениям: `detected_frames/` vs `lost_frames/`

**Результат**: Правильное разделение типов событий и путей к изображениям.

### Этап 8: Исправление масштабирования bounding boxes

**Проблема**: Координаты bounding box'ов масштабировались неправильно, используя фиксированные размеры изображения.

**Решение**:
- Исправлен `ImageDelegate.paint()` для использования реальных размеров изображения
- Добавлено получение оригинальных размеров изображения через `QPixmap`
- Правильное масштабирование координат: `scale_x = pixmap.width() / original_pixmap.width()`

**Результат**: Правильное масштабирование и позиционирование bounding boxes.

### Этап 9: Исправление имен файлов в JSON

**Проблема**: В JSON сохранялись имена файлов без камеры (например, `_frame.jpeg`), а реальные файлы содержали камеру (например, `_Cam1_frame.jpeg`).

**Решение**:
- Исправлен `ObjectsHandler._get_img_path()` для включения имени камеры в имя файла
- Исправлен `Controller._init_object_handler_without_db()` для передачи параметров камер в `ObjectsHandler`

**Результат**: JSON содержит правильные имена файлов с камерами.

## Структура данных

### Группировка событий:
```python
grouped_events = {
    object_id: {
        'found': found_event_data,
        'lost': lost_event_data
    }
}
```

### Строка таблицы:
```python
row_data = {
    'event': f"Object {object_id}",
    'time': found_timestamp or lost_timestamp,
    'time_lost': lost_timestamp,
    'information': f"Object Id={id}; class: {class}; conf: {confidence}",
    'preview': found_image_path,
    'lost_preview': lost_image_path
}
```

```json
{
```

## Известные ограничения

### Отсутствующие изображения:
- Изображения сохраняются только до определенного времени
- JSON данные содержат записи до более позднего времени
- Это нормальное поведение системы

### Отладочная информация:
- `ImageDelegate` выводит сообщения о отсутствующих файлах
- Это помогает понять, какие изображения не существуют

## Использование

### Настройка конфигурации:
```json
{
  "controller": {
    "use_database": false
  },
  "database": {
    "image_dir": "EvilEyeData"
  }
}
```

### Запуск системы:
```bash
python evileye/process.py --config configs/pipeline_capture.json --gui --no-autoclose
```

### Открытие журнала:
- В главном окне нажать кнопку "Journal" (когда `use_database=false`)
- Выбрать дату из выпадающего списка
- Выбрать тип событий (All/Found/Lost)
- Просматривать изображения с bounding box'ами
