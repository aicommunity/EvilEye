## Краткая архитектура

Контроллер публикует JPEG и метаданные в `FrameBroker`, иногда через IPC или внутренний HTTP-релей. FastAPI отдаёт REST, WS live preview, MJPEG и файловый playback. React SPA опрашивает состояние/журналы, подписывается на live WS и запрашивает дневные индексы архива. Горячие участки проходят через файловые сканы, фоновые потоки, браузерные таймеры и пересчёты timeline. Уже есть полезные механизмы: latest-wins очередь WS, TTL-кэши, отдельные пулы playback и пауза части опросов при скрытой вкладке. Ошибки ниже возникают на границах этих механизмов.

## Проверки и ограничения

- `TestClient` воспроизвёл A02: `GET /api/v1/runs/99123/snapshot?source_id=0` вернул 200 и JPEG другой камеры при наличии лишь общего кадра source 1. Проверка была без правки файлов.
- С `EVILEYE_PYTEST_NO_FORCE_EXIT=1` набор `test_snapshot_etag.py`, `test_journal_time.py`, `test_state_cache_ttl.py` дал **3 failed, 9 passed, exit 1**; все три падения — A14. Без переменной был **exit 0** из-за A05. Отдельно `test_journal_time.py` дал **3 passed, exit 0**.
- Полный `tests/unit/api` не собрался в локальной Python 3.13.7: отсутствует `itsdangerous`, хотя пакет объявлен в `pyproject.toml`. Часть запусков с `tmp_path` также упиралась в ограничение системного каталога Temp песочницы. Один time-based assert `<100 мс` в `test_state_cache_ttl.py:176` прошёл нестабильно (543 мс в одном прогоне); это не доказательство продуктовой регрессии.
- `npm test`/`npm run build` не запускались: в текущей среде нет `npm` и локальных `node_modules`. Сборка Vite переписывает отслеживаемую папку `evileye/api/static`, поэтому для CI нужен чистый checkout и явная проверка артефакта.
- Браузерный trace, нагрузочный стенд и реальные видеопотоки не использовались. Задержки B01–B07 — обоснованные кодом причины для профилирования, а не измеренные значения.

## План реализации и критерии готовности

### Этап 0 — восстановить доверие к проверкам и закрыть доступ к чужим данным

1. Исправить A05, A13 и A14; поднять чистую среду с зафиксированными зависимостями. CI должен возвращать ненулевой код при преднамеренно падающем тесте и проверять реальную Vite-сборку.
2. Исправить A01–A04 одной матрицей авторизации: администратор, ограниченный пользователь, пустой ACL, запрещённый `source_id`, отсутствие `subscribe`, смена ACL, составной MP4 и путь вне `Streams`. Утечек JPEG/событий/файлов быть не должно; разрешённые потоки продолжают работать.
3. Зафиксировать протокол WS: до явной подписки кадры не отправляются, `[]` значит ноль источников, `subscribe` заменяет прежний набор. Проверить бинарный и notify режимы.

### Этап 1 — исправить функциональные ошибки Live и playback

4. Исправить A06–A08. В notify режиме первый и каждый новый JPEG должен появляться без snapshot fallback; 304 допустим лишь для уже полученного кадра. При двух run с одинаковым source ID кадры не перемешиваются. Подтверждённо пустой ответ убирает устаревшие плитки.
