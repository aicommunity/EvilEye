# Архитектура системы истории конфигураций EvilEye (Обновленная)

## Обзор системы

Система истории конфигураций использует **существующую структуру базы данных** EvilEye для предоставления удобного интерфейса просмотра и восстановления конфигураций.

## Существующая структура БД

### Таблица `jobs` (уже существует)
```
┌─────────────────────────────────────┐
│               jobs                  │
├─────────────────────────────────────┤
│ job_id (SERIAL PRIMARY KEY)         │
│ creation_time (timestamp)           │
│ finish_time (timestamp)             │
│ is_terminated (boolean)             │
│ configuration_id (integer)          │
│ configuration_info (json)           │ ← Хранит полную конфигурацию
│ project_id (integer)                │
└─────────────────────────────────────┘
```

### Существующая функциональность
- ✅ **Автоматическое сохранение** конфигураций при запуске pipeline
- ✅ **Дедупликация** конфигураций через `configuration_id`
- ✅ **JobsHistory** журнал для просмотра истории заданий
- ✅ **Связь с проектами** через `project_id`

## Поток данных

### Автоматическое сохранение конфигурации (уже работает)
```
Controller.start_pipeline()
    ↓
DatabaseController.save_job_configuration_info()
    ↓
DatabaseController._check_if_config_exist()
    ↓
UPDATE jobs SET configuration_info = %s, configuration_id = %s
    ↓
Конфигурация сохранена в БД
```

### Восстановление конфигурации (новая функциональность)
```
User clicks "Restore" in JobsHistory
    ↓
ConfigHistoryManager.restore_config(job_id)
    ↓
DatabaseController.get_config_by_job_id(job_id)
    ↓
ConfigHistoryManager.create_backup(current_config)
    ↓
Write restored config to disk
    ↓
Notify MainWindow of config change
    ↓
Optionally restart pipeline
```

## Интеграция с существующими компонентами

### MainWindow
- Добавлен пункт меню "Configuration History" → открывает расширенный JobsHistory
- Статус-бар показывает последнюю конфигурацию из БД
- Уведомления о восстановлении конфигураций

### ConfigurerMainWindow
- Кнопка "Load from History" в toolbar
- Показ истории изменений текущей конфигурации
- Автоматическое предложение восстановления при ошибках
- Интеграция с существующим JobsHistory

### DatabaseJournalWindow
- Связь с JobsHistory для просмотра конфигураций
- Показ конфигурации для каждого события
- Быстрый доступ к истории конфигураций

### UnifiedLauncherWindow
- Вкладка "History" с быстрым доступом к последним конфигурациям
- Статистика использования конфигураций
- Связь с существующим журналом заданий

## События системы

### Новые события
- `config_restored_from_history` - конфигурация восстановлена из истории
- `config_backup_created` - создана резервная копия при восстановлении
- `config_history_exported` - экспортирована история конфигураций

### Существующие события (используются)
- `pipeline_started` - запуск pipeline (уже сохраняет конфигурацию)
- `pipeline_stopped` - остановка pipeline
- `database_connected` - подключение к БД
