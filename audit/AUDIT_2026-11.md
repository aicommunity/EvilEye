# Аудит проекта EvilEye — ноябрь 2026

- **Версия:** 0.0.17 (merge `main` → `develop`, коммит `44562dd5`)
- **Объём:** ~104k строк Python в пакете `evileye` (37 подмодулей), 410 тестовых файлов (1824 теста, сборка чистая), Web-SPA, Docker-развёртывание.
- **Метод:** 6 параллельных глубоких исследований: ядро/архитектура, Web API/безопасность, видеоконвейер, слой данных/события, тесты/CI/упаковка, GUI/визуализация. Все ключевые находки P1 проверены по коду повторно.

## 1. Общая архитектура

```
CLI / сервис-менеджер (typer, systemd/schtasks, watchdog)
        │
Controller (controller.py, 2731 стр.) ── ServiceLocator (9 сервисов: DB, events, recording…)
        │ run() — один поток, тик ~30 Гц
        ▼
Pipeline (pipeline_surveillance → pipeline_processors)
  sources → preprocessors → detectors → trackers → mc_trackers → attributes_roi → classifier
        │ (put + drain ≤64/тик; каждая стадия — плагин-модуль)
        ▼
Plugin Runtime (core/plugin_runtime)          MP-инфраструктура (core/mp_*)
  EvilEyeBase.create_instance → адаптер         MpControl (spawn-пул, рестарт-бюджеты)
  thread: queue.Queue(8) + поток                SHM-транспорт кадра на каждый put
  process: mp.Queue(8) + worker
        ▼
EventsProcessor → адаптеры (PG + JSON пишутся оба) → PostgreSQL / EvilEyeData
        ▼
Визуализация: Qt-GUI (visualization_modules, 36k стр.) и Web API (FastAPI, 21k стр.)
  — общий слой данных журналов (journal_data_source_db, preview_render)
```

**Вердикт:** зрелая модульная плагин-система поверх классического CV-конвейера, но с тремя системными слабостями:

1. **Нет сквозного backpressure** — единственный регулятор (skip-tick контроллера) «слеп» к plugin-рантайму (`MpPendingReporter` не реализован в адаптерах → `pending=0` при заполненных очередях), потери кадров размазаны по 5 несвязанным счётчикам. Это корень TD-PS-D7.
2. **God objects на каждом уровне:** `Controller` (2731 стр., `__init__` ~250 стр., ~60 полей), `MainWindow` (~2300), `VideoGridWidget` (~2100), `playback_service.py` (1460).
3. **Двойные реализации одной семантики:** thread/process-пути модулей, PG/JSON-адаптеры событий, три поколения журналов GUI (одно — 2670 строк мёртвого кода), три редактора конфигов (GUI-конфигуратор, main_window, Web), зависимости в трёх местах (pyproject + requirements.txt + docker-скрипт).

**Что сделано хорошо (сохранять):** плагин-модель с версионированным API и изоляцией сбойных плагинов; `error_policy` (skip/restart/fail_stop + degraded-окно); bounded-очереди везде с drop-oldest; MP на spawn с рестарт-бюджетами и PID-реестром; PBKDF2-390k + RBAC + rate-limit/bans + path-traversal-защита в Web; параметризованный SQL в основном DB-слое; baseline-ratchet для F821 в CI; RTSP-фикстуры с SHA-256 pinning; graceful teardown GStreamer с таймаутами.

### 2.2 Важные (P2)

**Ядро / конвейер:**
- B1. Двойной `_record_input_drop()` при вытеснении кадра — метрики потерь завышены (ими же мерили TD-PS-D7); при feeder-lag mp.Queue теряется и вытесненный, и новый кадр. `core/plugin_runtime/item.py:339-349`
- B2. Исключение в `stop()` одного процессора прерывает остановку остальных (`raise stop_error[0]` в цикле) → «полузомби» с живым RTSP. `core/pipeline_processors.py:220-242`, `core/processor_base.py:182-216`
- B3. GStreamer отдаёт дубликаты frame_id без проверки новизны (двойной апдейт BoT-SORT) + двойной инкремент `frame_id_counter` (для split — по разу на область) → метрики «уникальных frame_id» искажены. `capture/gstreamer_capture_frames.py:1170-1249, 687-688, 1136`
- B4. Потолок захвата: максимум 1 кадр/source/тик × 30 Гц контроллера — плохо масштабируется по числу камер. `capture/video_capture_base.py:276-318`
- B5. `release()` GStreamer берёт lifecycle-lock без таймаута (в `init()` таймаут добавили, здесь — нет). `capture/video_capture_gstreamer.py:407`
- B6. 11 bare `except:` + ~56 `except Exception: pass` в core; `_log_listener_loop` бесконечно глотает любые ошибки. `core/pipeline_base.py`, `core/mp_control.py:137-138`
- B7. Check-then-act race в `PipelineBase.add_result` (full→get→put без блокировки); неатомарные переливки очередей. `core/pipeline_base.py:113-311`
- B8. MpWorker: любая не-CUDA ошибка → exit code 0 (родитель не отличает чистый выход от падения). `core/mp_worker.py:150-156, 210-218`
- B9. Поток на каждый `retrieve()` в OpenCV-захвате. `capture/video_capture_opencv.py:493-527`
- B10. `run_config_helper`: busy-loop `processEvents()` без sleep (100% CPU) + глобальный `os.chdir`. `run_config_helper.py:66-74, 297-298`
- B11. Неограниченная `_log_queue` MpControl при умершем listener. `core/mp_control.py:88`

**Web / безопасность:**
- W1. f-string SQL с ручным экранированием в `journal_data_source_db.py:102-330` (`source_id` — вообще без экранирования). Инъекция через текущие HTTP-параметры недостижима, но паттерн готов к срабатыванию при расширении фильтров.
- W2. CSRF Origin-проверка только для `/api/v1/admin/*`; остальные не-GET — только SameSite=Lax. `api/app.py:89-93`
- W3. `/setup/test-database` — исходящие соединения на произвольный host:port (SSRF для админа); `/check-data-dir` — mkdir в любой точке ФС. `api/routes/setup.py:338-396`
- W4. `/ready` без аутентификации раскрывает пути internal-сокетов, метрики памяти, WS-баны. `api/app.py:377-494`
- W5. Non-constant-time сравнение internal-токена. `api/middleware/ip_protection.py:57`
- W6. `/auth/me` читает сессию напрямую без перепроверки principal (удалённый юзер видит `authenticated: true`). `api/routes/auth.py:120-127`
- W7. Мёртвый `routes/events.py` (203 строки закомментированных эндпоинтов, роутер не подключён).
- W8. 500-е раскрывают текст исключений (`detail=f"...{exc}"`). `routes/configs.py:156+`, `routes/extensions.py:246+`
- W9. CORS `*` methods/headers; `uvicorn(proxy_headers=True)` безусловно при app-level `trust_proxy=false`. `api/app.py:283`, `server.py:104,453`
- W10. Rate limiting только in-process; дубли утилит (`_configs_dir`, атомарная запись JSON ×3).

**Данные / события:**
- D1. `event_id = MAX+1` — не SERIAL; гонка при параллельных инстансах/перезапуске → PK-конфликты. `database_controller_pg.py:599-624`
- D2. В `events_tables` попадают JSON-имена `*_json` (фильтр `hasattr(get_table_name)` совпадает у всех адаптеров); при отключённом PG-адаптере UNION к несуществующей таблице падает → `get_next_event_id` = 0. `events_processor.py:63-73`
- D3. Writer-поток контроллера теряет записи без ретрая, логирует потерю как `info`. `database_controller_pg.py:368-369`
- D4. Нет ретеншна: таблицы и `EvilEyeData/` растут бесконечно; `append_json_record` переписывает весь дневной JSON-файл на каждое событие — O(n²). `json_event_io.py:20-30`
- D5. Дублирование ~200 строк истории конфигов (контроллер vs менеджер, с дрейфом). `database_controller_pg.py:626-813` vs `config_history_manager.py:55-254`
- D6. PG/JSON-адаптеры: двойная запись каждого события, нет общего слоя сериализации; пароль БД раздаётся всем адаптерам через `db_params`. `controller/services/events_service.py:361-371`, `db_adapter.py:17,172-173`
- D7. `query()` возвращает None при любой ошибке — неотличим от пустого результата; `stop()` writer'а — join без таймаута. `database_controller_pg.py:256-263`, `database_controller_base.py:75-80`
- D8. TD-PS-D8 подтверждён: schedule-alarm события без кадров (пустые preview_path). `event_schedule_alarm.py:4-14`, `db_adapter_fov_events.py:54-64`
- D9. SQLAlchemy — мёртвая зависимость (объявлена, не импортируется).
- D10. DDL-типы из `database_config.json` интерполируются как raw SQL (готовая инъекция, если конфиг когда-нибудь придёт извне). `database_controller_pg.py:426-428`

**GUI / визуализация:**
